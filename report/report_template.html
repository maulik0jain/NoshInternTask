0. Dataset — quick facts

  • 110 images, all 640×640 (Roboflow resized with "stretch")
  • Roboflow folder export → class labels only. No boxes, no masks.
  • README says no augmentation → checked: 110 unique source ids, 0 copies

1. Task 1 — ground truth with pretrained models

Model choice

  • SAM 2.1 needs a prompt (point / box) — it doesn't find eggs on its own
  • Dataset has no boxes → Grounding DINO (open-vocabulary detector) turns the text "egg." into boxes
  • Each box → SAM 2.1 Hiera Base+ → mask
  • Why not the lightest model: GT is made once, offline. Every GT mistake later counts as a mistake of my classical method → spend compute here
  • Why not SAM "segment everything": it also segments hands, floor, shadows → messy filtering
  • Also considered SAM 3 (text prompt built in) — heavier (~850M params) and gated weights; Grounding DINO + SAM 2.1 was enough

Pipeline

  1. Grounding DINO base, prompt "egg.", box thr 0.30, text thr 0.25
  2. Box cleanup: NMS (IoU 0.5), drop boxes >95% of the image, drop a "group" box that contains ≥2 other boxes
  3. SAM 2.1, one mask per box (a box prompt isn't ambiguous → single-mask output)
  4. Mask cleanup: clip to box (+6 px), fill holes (specular highlights), drop specks <15% of the biggest piece
  5. Drop duplicate masks (>50% covered by a more confident egg)
  6. Manual review overrides — 2 images, see below
  7. Save binary mask, instance mask (ids left → right), overlay, annotations.json

2. Task 2a — dev / eval split (4:1)

Why a random split is wrong here

  • Photos were shot in sessions: same pot, same keyboard, same bag, same hand — different angles
  • Random split → same scene in dev and eval → tune thresholds on a scene, then "test" on the same scene → eval looks better than it is
  • Same idea as splitting by subject, not by frame

Steps

  1. Augmented copies: strip .rf.<hash> → source id. 110 ids, 0 duplicates
  2. Near-identical shots: pHash (64-bit DCT), Hamming ≤ 10 → 1 pair, same group
  3. Same scene: DINOv2-small embeddings (CLS + mean patch), average-linkage clustering, cosine distance 0.30 → 35 groups
    • 0.30 picked by looking at the groups. 0.40 merged marble floor with grey floor (19 images) and still split the pot
  4. Manual merges (8): same physical setup the embedding kept apart — pot, keyboard, fridge tray, white bag + holder, pink bowl, painted lid, grey floor, towel + rug → scene_merges.json → 19 groups
  5. Split whole groups. Rules: eval = 17–23% of images; multi-egg share within ±5 points of overall; then as many scenes as possible. Seeded search (seed 42)
    • Try 1: StratifiedGroupKFold → valid, but eval had only 4 scenes
    • Try 2: soft penalty → 7 scenes, but only 1 multi-egg image in eval (too easy) → made the multi-egg share a hard rule

3. Task 2b — classical segmentation

Idea in one line

  • An egg here = a bright, almost colourless, egg-shaped blob. No single threshold separates it from every background → try many thresholds, keep the blobs that look most like an ellipse, then fix their edges with GrabCut and split touching eggs with watershed

Final algorithm ({{final.trial}}) — stages and parameters

  1. Blur: Gaussian {{final.pipeline.preprocess.blur}}×{{final.pipeline.preprocess.blur}} — shell texture and JPEG noise make ragged blob outlines
  2. Colour gate — remove pixels that can't be egg before any thresholding
    • Skin: YCbCr box Cb {{final.pipeline.skin.cb.0}}–{{final.pipeline.skin.cb.1}}, Cr {{final.pipeline.skin.cr.0}}–{{final.pipeline.skin.cr.1}} (Chai & Ngan 1999) → hands / fingers out. Turned out to also remove warm-lit egg pixels — see the §4 ablation
    • Saturation: HSV S ≤ {{final.pipeline.saturation.s_max}} → coloured bowls, leaves, pink lids out (eggs are white / grey)
  3. Multi-threshold egg search on the Lab L* channel (my own stage, similar idea to MSER)
    • {{final.pipeline.candidate.levels}} thresholds, evenly spaced between the {{final.pipeline.candidate.pct_range.0}}th and {{final.pipeline.candidate.pct_range.1}}th percentile of L* in that image
    • At each: L* ≥ t AND colour gate → opening {{final.pipeline.candidate.open}} px (cuts thin bridges to background) → connected components → fill holes
    • Shape check per blob: area {{final.pipeline.components.min_area}}–{{final.pipeline.components.max_area}} of the image, solidity ≥ {{final.pipeline.components.min_solidity}}, axis ratio ≤ {{final.pipeline.components.max_axis_ratio}}, ≤ {{final.pipeline.components.max_border_frac}} of the outline on the image border
    • Egg score = IoU(blob, its fitted ellipse) × solidity — an egg seen from above is ~1.0; background blobs are not. Keep score ≥ {{final.pipeline.candidate.min_score}}
    • Pick greedily, best score first. The same egg shows up at several thresholds (nested blobs) → take the largest one within {{final.pipeline.candidate.score_tol}} of the best score, so the egg isn't shrunk to its bright centre. Skip blobs that overlap a picked egg by > {{final.pipeline.candidate.max_overlap}}
    • Fallback: if nothing reaches {{final.pipeline.candidate.min_score}}, search once more with score ≥ {{final.pipeline.candidate.fallback_min_score}} (only images that would otherwise be empty)
  4. Morphology: opening {{final.pipeline.morphology.open}} px, closing {{final.pipeline.morphology.close}} px, fill holes (specular highlights inside eggs)
  5. GrabCut (Rother 2004) on the original colours, seeded from the mask
    • Mask eroded by {{final.pipeline.grabcut.erode}} px = sure egg · mask = probably egg · up to {{final.pipeline.grabcut.bg_dilate}} px around it = probably background · further away = sure background
    • {{final.pipeline.grabcut.iters}} iterations, fixed RNG seed; new blobs that don't touch the seed are dropped
    • Why: the search finds the lit part of the egg. The shaded side is often darker than parts of the background, so no threshold gets it — a colour model (GMM + graph cut) can
  6. Watershed (Vincent & Soille 1991) on the distance transform of each blob: cores = pixels ≥ {{final.pipeline.watershed.peak_rel}} × max distance (≥ {{final.pipeline.watershed.min_core_px}} px) → one instance per core. Splits touching eggs (needed for Task 4)
  • Output: binary mask + instance mask per image. {{final.eval.seconds_per_image:.2f}} s / image on CPU (most of it GrabCut)
  • Code: src/eggseg/classical.py (one small function per stage), parameters: configs/default.yaml + experiments/{{final.trial}}/config.yaml

How I ran experiments

  • Each trial = a folder experiments/Tn/ with config.yaml: which trial it builds on, what changed, why, decision + reason (written after the run)
  • run_experiment.py runs it on the 85 dev images → results.json, per-image CSV, worst-case panels. Small parameter sweeps with sweep.py, also dev only
  • Decision rule (fixed before starting): keep a change if dev mean IoU goes up; if IoU ties, keep only if boundary F1 or instance F1 improves
  • Metrics (same code as Task 3): IoU, Dice, pixel precision / recall, boundary F1 (2 px), instance F1 (match at IoU ≥ 0.5), number of empty predictions
  • Table and per-trial notes below are generated from those files (build_log.py → experiments/LOG.md), not typed

How the experiments led to the algorithm

4. Task 3 — evaluation & analysis

Setup

  • GT = Task 1 SAM 2.1 masks, prediction = final pipeline {{final.trial}}, frozen before eval was opened
  • final_eval.py ran dev + eval once ({{final.run_at}}); analyze.py makes every number and plot below from its saved outputs
  • Metrics and why:
    • IoU / Dice — overall overlap, the "match Task 1 quality" number. Per image, then averaged (an empty prediction counts as 0)
    • Pixel precision / recall — tells over- vs under-segmentation apart
    • Boundary F1 at 2 px — edge quality; IoU is forgiving on big eggs
    • Instance precision / recall / F1 (match at IoU ≥ 0.5) and exact egg count — what Task 4 tracking needs

Almost all of it is the skin box, not saturation (diagnostics.csv)
  • Hand in the image: mean IoU {{fac.all.hand.yes.iou_mean:.2f}} vs {{fac.all.hand.no.iou_mean:.2f}}. On eval all {{fac.eval.hand.yes.n}} hand images score {{fac.eval.hand.yes.iou_mean:.0f}} — the dark-room / backlit shots
  • Brightness, egg size: weak (ρ = {{fac.all.spearman_iou_vs_brightness}} and {{fac.all.spearman_iou_vs_egg_area}}). Bright images are often white backgrounds, hence the slight negative trend
  • Egg count: multi-egg images do better (2 eggs {{fac.all.egg_count.2.iou_mean:.2f}}, 3 eggs {{fac.all.egg_count.3.iou_mean:.2f}}, 1 egg {{fac.all.egg_count.1.iou_mean:.2f}}) — they were shot on high-contrast surfaces (steel pot, marble), so this is a scene effect, not a count effect

  • Fails: backgrounds as bright and colourless as the egg — fridge tray {{fac.all.background.fridge_tray.iou_mean:.2f}}, white bag {{fac.all.background.white_bag.iou_mean:.2f}}, pale tiles {{fac.all.background.tiles.iou_mean:.2f}} — and ash {{fac.all.background.ash.iou_mean:.2f}} (egg dusted with the same grey). Failure taxonomy

  • Failure = IoU < {{tax.fail_iou_below}} → {{tax.failed_images}} images (dev + eval)
  • I looked at every one (sheets in results/analysis/failures/) and gave each one primary cause → failure_labels.csv
{{@taxonomy_table}}
  • How labelled: (1) if most of the error is missed egg (FN > FP) and the colour gate removed ≥ 40% of the egg → "colour gate removes egg"; (2) otherwise by eye from the failure sheet. Notes per image in failure_labels.csv
  • White / pale background ({{tax.counts.white / pale background}}) — no threshold separates egg from bag / tray / wall; the blob that comes out isn't egg-shaped → egg missed, or the bag picked instead
  • Shaded side missed ({{tax.counts.shaded side missed}}) — search keeps the lit half; the shaded half is darker than the surface next to it, and GrabCut only partly recovers it
  • Colour gate removes egg ({{tax.counts.colour gate removes egg}}) — the Chai & Ngan skin box also matches cream eggs, eggs under warm light, and backlit eggs. All 3 eval misses in the dark-room scene are this (84–98% of the egg removed)
  • Bright object picked ({{tax.counts.bright object picked}}) — keyboard keys, foil, polished steel: bright, colourless and convex enough to pass the egg score
  • Egg partly hidden ({{tax.counts.egg partly hidden}}) — leaves, tray bars, boiling water: the visible part isn't egg-shaped
  • Ash camouflage ({{tax.counts.ash camouflage}}) — egg dusted with ash, lying on ash: same grey, same texture; either nothing egg-shaped is found or the ash patch is taken with the egg
  • Touching eggs ({{tax.counts.touching eggs}}) — the merged blob of 3 touching eggs fails the shape score before watershed ever sees it

Ablation — what each stage still adds (dev, after the eval run)

  • Final pipeline with one stage switched off at a time, dev only (ablation.py). Several stages were accepted early, on top of a much simpler method — do they still help?
  • Run after the eval run, as part of this analysis → nothing here changes the reported pipeline or its eval numbers
{{@ablation_table}}
  • GrabCut is the most important stage: without it IoU {{abl:no GrabCut|iou_mean:.3f}}, boundary F1 {{abl:no GrabCut|boundary_f1:.3f}}
  • Fallback pass: removing it gives back exactly T10 ({{abl:no fallback pass|empty}} empty masks) → the IoU / instance-F1 trade-off from the log
  • Watershed: same IoU by design, instance F1 {{abl:no watershed|instance_f1:.3f}} → {{abl:final pipeline|instance_f1:.3f}}. Only 5 images have touching eggs
  • The skin filter now hurts: without it dev IoU goes {{abl:final pipeline|iou_mean:.3f}} → {{abl:no skin filter|iou_mean:.3f}}. It helped in T3, when the candidate was one Otsu threshold that grabbed whole hands. The shape search ignores hands anyway (not egg-shaped), so the skin box now mostly deletes warm-lit egg pixels — the same thing the colour-gate diagnostic and the failure taxonomy show. Lesson: re-check early decisions once the pipeline around them changes
  • I did not switch it off in the final pipeline: that would be a change made after seeing eval results, and the eval run would no longer be a clean test. It's the first item below

Performance gaps → what I'd improve

  1. Colour gate ({{tax.counts.colour gate removes egg}} failures + part of "shaded side"). Drop the skin box, or only remove skin regions that are large and touch the image border (hands come in from the edge). Dropping it alone: dev IoU {{abl:final pipeline|iou_mean:.3f}} → {{abl:no skin filter|iou_mean:.3f}} (ablation above)
  2. White / pale backgrounds ({{tax.counts.white / pale background}}, the biggest group). Brightness and colour carry no signal there → use edges and shading: an egg is a smooth closed outline with a soft shading gradient and a cast shadow. E.g. ellipse detection on edges (Hough / RANSAC on Canny), or a gradient term in the egg score
  3. Shaded side missed ({{tax.counts.shaded side missed}}). The search finds the lit cap; give GrabCut the cap's fitted ellipse (slightly enlarged) as "probably egg". T9 forced the ellipse as the final mask, which was too strong; as a GrabCut seed the colour model still decides
  4. False eggs on keys, foil, steel ({{tax.counts.bright object picked}}) and from the fallback pass. Add a check for straight edges / corners and high-frequency texture — eggs have neither
  5. Touching eggs: split merged blobs with watershed before the shape score, so 2–3 touching eggs aren't rejected as one non-egg blob
  6. Evaluation itself: GT is SAM pseudo-GT, so boundary F1 at 2 px also counts SAM's edge error; a few hand-drawn masks would show how much of the gap is the GT. Eval has only 5 scenes → per-scene numbers say more than the mean
  • Bottom line: the method does well when the egg is the brightest, least-coloured, egg-shaped thing in view (IoU ≥ 0.8 on {{tab.eval.n_good}} / {{tab.eval.images}} eval images), and fails completely when that's not true. Closing the rest of the gap to SAM needs cues beyond brightness — edges, shading, context
