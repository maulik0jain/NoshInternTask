## Trials

### T0 - Otsu threshold on grayscale (baseline)

- **Builds on:** default
- **Why:** Eggs are usually the brightest thing in the photo; Otsu picks the bright/dark split with no tuning.
- **Params changed:** `{}`
- **Dev:** IoU 0.366 (median 0.273), Dice 0.486, P 0.407, R 0.879, BF1 0.158, instance F1 0.008, empty masks 0
- **Decision:** baseline - Reference point. High recall but low precision: Otsu takes every bright region, not just the egg.

### T1 - Otsu on CIE Lab L* instead of grayscale

- **Builds on:** T0
- **Why:** L* is perceptual lightness and ignores colour, so e.g. a saturated pink bowl is not "brighter" than it looks.
- **Params changed:** `{"candidate": {"channel": "L"}}`
- **Dev:** IoU 0.340 (median 0.256), Dice 0.461, P 0.373, R 0.896, BF1 0.143, instance F1 0.007, empty masks 0
- **Decision:** discarded - IoU fell (vs T0). With one global threshold, L* lets in even more bright background. Re-tested later inside the multi-threshold search (T7c), where it won.

### T2 - + gray-world white balance and CLAHE on L*

- **Builds on:** T1
- **Why:** Warm bulbs tint white eggs cream; CLAHE lifts eggs in dim/backlit photos.
- **Params changed:** `{"preprocess": {"white_balance": true, "clahe": {"enabled": true, "clip": 2.0, "tile": 8}}}`
- **Dev:** IoU 0.266 (median 0.206), Dice 0.389, P 0.282, R 0.875, BF1 0.077, instance F1 0.005, empty masks 0
- **Decision:** discarded - IoU fell sharply. Gray-world shifts colours in scenes dominated by one colour (pink bowl, green leaves), and CLAHE brightens the background as much as the egg, so Otsu took more background.

### T3 - + remove skin pixels (YCbCr box, Chai & Ngan 1999)

- **Builds on:** T0
- **Why:** 14 images have a hand; a lit palm is as bright as the egg and gets swallowed by Otsu.
- **Params changed:** `{"skin": {"enabled": true}}`
- **Dev:** IoU 0.377 (median 0.290), Dice 0.496, P 0.451, R 0.815, BF1 0.159, instance F1 0.007, empty masks 0
- **Decision:** kept - IoU and precision up vs T0; palms stop being swallowed with the egg.

### T4 - + keep only low-saturation pixels (HSV S <= 60)

- **Builds on:** T3
- **Why:** Eggs are white/cream (near-colourless); many bright backgrounds are coloured (pink bowl, green leaves, wood, rugs).
- **Params changed:** `{"saturation": {"enabled": true, "s_max": 60}}`
- **Dev:** IoU 0.392 (median 0.292), Dice 0.509, P 0.470, R 0.815, BF1 0.172, instance F1 0.008, empty masks 0
- **Decision:** kept - IoU up vs T3. Sweep T4_s_max: 25 and 40 tie, 40 used from T5b on because it is gentler on cream eggs.

### T5 - k-means (k=3) in Lab instead of Otsu; keep the brightest, least-coloured cluster

- **Builds on:** T3
- **Why:** Otsu splits the histogram in two; with 3 clusters, egg / bright background / dark background can separate.
- **Params changed:** `{"candidate": {"method": "kmeans", "k": 3, "chroma_weight": 1.0}}`
- **Dev:** IoU 0.408 (median 0.333), Dice 0.530, P 0.523, R 0.741, BF1 0.189, instance F1 0.013, empty masks 0
- **Decision:** kept - Better than Otsu (T4) as the candidate generator: IoU and precision up.

### T5b - k-means candidate + low-saturation filter (S <= 40, from the T4 sweep)

- **Builds on:** T5
- **Why:** T4 and T5 helped separately; check whether they stack.
- **Params changed:** `{"saturation": {"enabled": true, "s_max": 40}}`
- **Dev:** IoU 0.415 (median 0.333), Dice 0.536, P 0.531, R 0.740, BF1 0.194, instance F1 0.015, empty masks 0
- **Decision:** kept - T4 and T5 stack: IoU up again.

### T6 - + morphology (open r=3, close r=7, fill holes)

- **Builds on:** T5b
- **Why:** Raw masks are speckled (ash, rug texture) and have holes at specular highlights and dirt marks.
- **Params changed:** `{"morphology": {"enabled": true, "open": 3, "close": 7, "fill_holes": true}}`
- **Dev:** IoU 0.416 (median 0.340), Dice 0.536, P 0.532, R 0.759, BF1 0.216, instance F1 0.091, empty masks 0
- **Decision:** kept - IoU about the same, boundary F1 and instance F1 clearly up (fewer specks, filled highlights).

### T7 - + connected-component filters (area, solidity, axis ratio, border contact)

- **Builds on:** T6
- **Why:** Precision is the problem (~0.5); most false positives are big, irregular or border-hugging bright background regions.
- **Params changed:** `{"components": {"enabled": true}}`
- **Dev:** IoU 0.312 (median 0.000), Dice 0.365, P 0.744, R 0.349, BF1 0.184, instance F1 0.482, empty masks 36
- **Decision:** discarded - IoU fell and 36 dev images got an empty mask: one global threshold glues the egg to bright background (ash, cables, white bag, towel), so the shape filter throws the egg away together with the background. Sweep T7_open: stronger opening helps but stays below T6.

### T7b - Multi-threshold egg search (24 thresholds, blobs scored by ellipse fit x solidity) replaces the single Otsu/k-means threshold

- **Builds on:** T6
- **Why:** T7 failed because one global threshold glues the egg to bright background, so the shape filter throws both away (36 empty images). Trying many thresholds gives the egg a chance to separate at some level.
- **Params changed:** `{"candidate": {"method": "search", "channel": "gray"}, "components": {"enabled": false}}`
- **Dev:** IoU 0.448 (median 0.466), Dice 0.541, P 0.879, R 0.464, BF1 0.249, instance F1 0.473, empty masks 12
- **Decision:** kept - Best so far and precision up a lot; fixes the T7 failure mode. Sweeps: min_score 0.75 and 0.8 tie on mean IoU, 0.8 kept for its better median and instance F1; s_max 40 still best.

### T7c - Search on Lab L* instead of grayscale (from the T7b channel sweep)

- **Builds on:** T7b
- **Why:** T1 rejected L* with a single Otsu threshold; with shape-scored multi-threshold search the comparison can come out differently, so it was re-tested.
- **Params changed:** `{"candidate": {"channel": "L"}}`
- **Dev:** IoU 0.464 (median 0.483), Dice 0.565, P 0.902, R 0.483, BF1 0.257, instance F1 0.493, empty masks 11
- **Decision:** kept - IoU up vs T7b: the channel sweep reverses the T1 result once candidates are chosen by shape.

### T8 - + GrabCut refinement seeded from the mask (eroded = sure egg, >70 px outside = sure background)

- **Builds on:** T7c
- **Why:** The search under-segments (precision ~0.88, recall ~0.48) - it often keeps only the bright cap of the egg. GrabCut's colour models can grow the mask out to the real egg edge.
- **Params changed:** `{"grabcut": {"enabled": true, "iters": 5, "erode": 10, "bg_dilate": 70}}`
- **Dev:** IoU 0.566 (median 0.654), Dice 0.652, P 0.894, R 0.605, BF1 0.445, instance F1 0.608, empty masks 11
- **Decision:** kept - Largest single gain: GrabCut grows the egg cap out to its real edge (recall and boundary F1 up). bg_dilate 70 chosen by sweep T8_bg_dilate. Two code fixes found here: fixed RNG seed (runs were not repeatable) and drop GrabCut blobs that don't touch the seed (they were new background objects).

### T9 - + ellipse regularisation (blobs with ellipse IoU >= 0.9 are replaced by their fitted ellipse)

- **Builds on:** T8
- **Why:** Eggs are near-elliptical from most viewpoints; snapping clean blobs to the ellipse should fix dents from highlights/shadows on the outline. Irregular blobs (eggs behind fingers/leaves) are left alone because the GT only covers the visible part.
- **Params changed:** `{"ellipse": {"enabled": true, "min_fit_iou": 0.9, "mode": "replace"}}`
- **Dev:** IoU 0.561 (median 0.644), Dice 0.648, P 0.887, R 0.603, BF1 0.331, instance F1 0.608, empty masks 11
- **Decision:** discarded - IoU slightly down and boundary F1 down a lot: real egg outlines are egg-shaped (one blunt end), not ellipses, so snapping moves correct edges. Stricter fit (sweep T9_min_fit_iou) still loses.

### T10 - + distance-transform watershed to split touching eggs into separate instances

- **Builds on:** T8
- **Why:** 5 images have touching eggs; a merged blob counts as zero correct instances. Binary IoU barely changes; instance F1 should.
- **Params changed:** `{"watershed": {"enabled": true, "peak_rel": 0.6, "min_core_px": 30}}`
- **Dev:** IoU 0.566 (median 0.654), Dice 0.652, P 0.894, R 0.605, BF1 0.445, instance F1 0.618, empty masks 11
- **Decision:** kept - Binary IoU unchanged (as expected), instance F1 up: touching eggs now come out as separate objects. Needed for Task 4 tracking.

### T11 - Fallback pass with a looser shape score (0.65) for images where the search found nothing

- **Builds on:** T10
- **Why:** 11 dev images still get an empty mask (IoU 0). The min_score sweep showed 0.6 leaves only 2 empty but hurts the other images, so the looser score is applied only where the strict pass found nothing.
- **Params changed:** `{"candidate": {"fallback_min_score": 0.65}}`
- **Dev:** IoU 0.589 (median 0.660), Dice 0.680, P 0.833, R 0.639, BF1 0.458, instance F1 0.569, empty masks 2
- **Decision:** kept - IoU up and empty masks 11 -> 2 (the two left, #30 and #155, are white eggs in front of a white bag / white wall: at every threshold the egg merges with the background, so no egg-shaped blob exists). Cost: instance F1 down, because on hard images the looser pass also returns non-egg blobs. Sweep T11_fallback_min_score: 0.65 has the best IoU; 0.72 gives better instance F1 but loses IoU.

### T11b - Fallback pass returns at most 1 egg

- **Builds on:** T11
- **Why:** T11 removed 9 of 11 empty masks but its looser score also picked wrong blobs (precision and instance F1 down). An image that needs the fallback is a hard image; taking only its single best egg should keep the gain without the extra false eggs.
- **Params changed:** `{"candidate": {"fallback_max_eggs": 1}}`
- **Dev:** IoU 0.579 (median 0.660), Dice 0.667, P 0.821, R 0.618, BF1 0.456, instance F1 0.603, empty masks 2
- **Decision:** discarded - Instance F1 recovers most of what T11 lost, but IoU falls. Only 4 dev images change, all with 1 GT egg: on these hard images the best-scoring fallback blob is often not the egg (#118: the egg was one of T11's 3 blobs, the cap kept a background one). The score can't rank egg vs background here, so capping doesn't help. IoU first -> T11 stays final.

### T12 - skin filter off

- **Builds on:** T11
- **Why:** Round-1 analysis: in 12 images the skin box removes >= 40% of the egg (cream eggs, warm light, backlit eggs); those images average IoU 0.29. The skin filter was accepted in T3, when the candidate was one Otsu threshold that grabbed whole hands. The egg-shape search should reject hands on its own.
- **Params changed:** `{"skin": {"enabled": false}}`
- **Dev:** IoU 0.609 (median 0.667), Dice 0.696, P 0.835, R 0.657, BF1 0.477, instance F1 0.573, empty masks 2
- **Decision:** kept - IoU 0.589 -> 0.609. The shape search already rejects hands (not egg-shaped), so the skin box mostly removed warm-lit egg pixels: #100 0.22 -> 0.90, #140 0.30 -> 0.91 (same trend as the round-1 ablation).

### T12b - skin filter only removes large skin regions that touch the image border

- **Builds on:** T11
- **Why:** Keep what the skin filter is for (hands come into the photo from the edge) without deleting egg-sized warm/cream regions in the middle of the image.
- **Params changed:** `{"skin": {"mode": "border_regions", "min_region": 0.02, "close": 7}}`
- **Dev:** IoU 0.592 (median 0.660), Dice 0.683, P 0.835, R 0.642, BF1 0.462, instance F1 0.571, empty masks 2
- **Decision:** discarded - Better than T11 but well below T12. On warm marble floors the floor itself is in the skin box and forms one big region touching the border, which takes the egg's warm side with it (#100: 0.22 vs 0.90 with T12, #140: 0.30 vs 0.91). Only 2 images are > 0.05 better than T12.

### T13 - GrabCut also gets each egg's fitted ellipse (x1.15) as 'probably egg'

- **Builds on:** T12
- **Why:** 15 round-1 failures are 'shaded side missed': the search keeps the lit cap and GrabCut only partly grows it. Marking the enlarged ellipse as probable egg puts the shaded side into the egg colour model from the start.
- **Params changed:** `{"grabcut": {"ellipse_prior": 1.15}}`
- **Dev:** IoU 0.646 (median 0.717), Dice 0.726, P 0.807, R 0.721, BF1 0.517, instance F1 0.615, empty masks 2
- **Decision:** kept - Recall 0.657 -> 0.721 and boundary F1 up: the shaded side now gets into GrabCut's egg colour model. Precision drops a little (the ellipse is slightly larger than some eggs). Beats the T13b alternative.

### T13b - Local Otsu growth around each found egg before GrabCut

- **Builds on:** T12
- **Why:** Same failure as T13, different fix: the threshold that isolates the egg globally is too high for its shaded side. Re-threshold locally (Otsu inside the egg's ellipse x1.4) and add connected pixels inside the ellipse x1.15.
- **Params changed:** `{"grow": {"enabled": true, "roi_scale": 1.4, "keep_scale": 1.15}}`
- **Dev:** IoU 0.633 (median 0.727), Dice 0.717, P 0.823, R 0.691, BF1 0.493, instance F1 0.588, empty masks 2
- **Decision:** discarded - Helps (T12 0.609 -> 0.633) but less than T13 (0.646), with lower boundary F1 and instance F1: a local Otsu threshold still cuts the shaded side wherever it is darker than the surface beside it, while GrabCut's colour model can include it.

### T13c - T13 + local Otsu growth (both shaded-side fixes together)

- **Builds on:** T13
- **Why:** T13 and T13b attack the same failure differently; check whether they add up.
- **Params changed:** `{"grow": {"enabled": true, "roi_scale": 1.4, "keep_scale": 1.15}}`
- **Dev:** IoU 0.645 (median 0.716), Dice 0.727, P 0.788, R 0.738, BF1 0.502, instance F1 0.626, empty masks 2
- **Decision:** discarded - No gain over T13 alone (IoU 0.645 vs 0.646, boundary F1 lower). Once GrabCut has the ellipse prior, the extra pixels from local growth are mostly ones GrabCut already adds, plus some background (precision down).

### T14 - Split non-egg-shaped blobs with watershed inside the search and score each piece

- **Builds on:** T13
- **Why:** Touching eggs merge into one blob that fails the egg-shape score and is thrown away before the watershed stage ever sees it (round-1 #144: 2 of 3 eggs missed).
- **Params changed:** `{"candidate": {"split_merged": true, "split_peak_rel": 0.6, "split_min_core_px": 30}}`
- **Dev:** IoU 0.650 (median 0.717), Dice 0.732, P 0.804, R 0.740, BF1 0.524, instance F1 0.617, empty masks 2
- **Decision:** kept - Small IoU gain (0.646 -> 0.650) and recall up. Its target #144 is unchanged (0.27); the gain comes from other touching eggs, e.g. #136 now has 2 of 3 eggs matched instead of 1. Also #111 0.35 -> 0.98 (single egg on a pale surface, probably joined to it at the threshold where the whole egg shows up).

### T15 - Egg score also rewards blob outlines that lie on Canny edges (weight 0.5)

- **Builds on:** T13
- **Why:** 18 round-1 failures are white / pale backgrounds: a threshold cut through a flat white bag has no image edge under it, a real egg outline does. Weighting the score by edge support should prefer real eggs over bag patches.
- **Params changed:** `{"candidate": {"edge_weight": 0.5, "edge_tol": 2, "canny": [30, 90]}}`
- **Dev:** IoU 0.339 (median 0.000), Dice 0.379, P 0.685, R 0.379, BF1 0.306, instance F1 0.406, empty masks 33
- **Decision:** discarded - Failed: IoU 0.339 and 33 empty masks. Design flaw, not a bad idea: multiplying the score by (0.5 + 0.5 * edge support) lowers every score, so most real eggs fell below the 0.80 cut that was tuned for the plain score. Fixed in T15c (edge support only ranks).

### T15b - Add ellipses fitted to Canny edge chains as extra egg candidates

- **Builds on:** T13
- **Why:** On a white background no threshold separates the egg at all, so the search has nothing to score. The outline is still an edge: fit ellipses to edge chains, keep those with >= 60% of the perimeter on edges.
- **Params changed:** `{"candidate": {"edge_candidates": true, "edge_min_support": 0.6, "edge_min_pts": 40, "canny": [30, 90]}}`
- **Dev:** IoU 0.573 (median 0.647), Dice 0.663, P 0.705, R 0.728, BF1 0.462, instance F1 0.477, empty masks 2
- **Decision:** discarded - Failed: IoU 0.646 -> 0.573. On its targets it changed nothing (white bag 0.36 -> 0.36, fridge tray and rice unchanged). Instead textured backgrounds produced many edge-chain ellipses: ash 0.38 -> 0.15 (predicted eggs 15 -> 29), towel 0.65 -> 0.36.

### T15c - Edge support only ranks candidates; the 0.80 cut stays on the plain shape score

- **Builds on:** T13
- **Why:** T15's idea (prefer blobs whose outline lies on image edges, not threshold cuts through a white bag) without its flaw (weighted scores fell below the cut).
- **Params changed:** `{"candidate": {"edge_weight": 0.5, "edge_rank_only": true, "edge_tol": 2, "canny": [30, 90]}}`
- **Dev:** IoU 0.652 (median 0.727), Dice 0.729, P 0.801, R 0.737, BF1 0.523, instance F1 0.608, empty masks 2
- **Decision:** kept - IoU 0.646 -> 0.652, boundary F1 up: among candidates that already pass the shape cut, the one whose outline sits on real edges wins, instead of a threshold cut through a white background. Instance F1 slightly down (0.615 -> 0.608).

### T16 - Reject rectangular blobs (area / min bounding rect > 0.9) and textured blobs (mean |Laplacian| > 5)

- **Builds on:** T13
- **Why:** Round-1 false eggs on keyboard keys, foil and steel. Measured on the dev GT eggs: 99% have rectangularity <= 0.83 (an ellipse is 0.785) and texture <= 4.6, so both limits keep real eggs.
- **Params changed:** `{"components": {"max_rectangularity": 0.9}, "candidate": {"max_texture": 5.0}}`
- **Dev:** IoU 0.655 (median 0.727), Dice 0.733, P 0.818, R 0.720, BF1 0.527, instance F1 0.639, empty masks 2
- **Decision:** kept - IoU 0.646 -> 0.655 and instance F1 0.615 -> 0.639: key caps, foil and other rectangular or crinkled blobs no longer pass as eggs, and the limits (from the dev GT eggs) don't touch real eggs.

### T17 - All kept round-2 changes together: T13 + T14 + T15c + T16

- **Builds on:** T16
- **Why:** T14, T15c and T16 were each tested alone on top of T13. Check that they add up when combined.
- **Params changed:** `{"candidate": {"split_merged": true, "split_peak_rel": 0.6, "split_min_core_px": 30, "edge_weight": 0.5, "edge_rank_only": true, "edge_tol": 2, "canny": [30, 90]}}`
- **Dev:** IoU 0.660 (median 0.728), Dice 0.733, P 0.802, R 0.744, BF1 0.540, instance F1 0.647, empty masks 2
- **Decision:** kept - The changes add up: IoU 0.660 (best), boundary F1 0.540, instance F1 0.647, all above each single change. Base for the round-2 sweeps; the final round-2 pipeline is T18.

### T18 - T17 with edge weight 0.3 (from sweep T17_edge_weight)

- **Builds on:** T17
- **Why:** Sweep on T17: edge weight 0.3 gave the best dev IoU and instance F1. Texture limit stays 5.0: 3.5 scored about the same but started rejecting real eggs (one more empty mask), and 5.0 is the limit backed by the dev GT measurement.
- **Params changed:** `{"candidate": {"edge_weight": 0.3}}`
- **Dev:** IoU 0.669 (median 0.732), Dice 0.742, P 0.811, R 0.744, BF1 0.544, instance F1 0.658, empty masks 2
- **Decision:** kept - Best dev IoU of both rounds (0.669, median 0.732), instance F1 0.658. Final round-2 pipeline (configs/final_round2.yaml).
